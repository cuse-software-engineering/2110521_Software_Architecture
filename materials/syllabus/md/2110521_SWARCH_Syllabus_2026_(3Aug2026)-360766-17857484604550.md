## ข้อ 14 — ประมวลการเรียนรายวิชา (Course outline)

### วัตถุประสงค์ทั่วไป และ/หรือ วัตถุประสงค์เชิงพฤติกรรม

- To introduce software architecture principle
- To survey available software architectural styles
- To practice the software architectural design using styles and patterns
- To exploit the conventional software tools in software architectural design

### เนื้อหารายวิชาโดยละเอียด

หลักการทางสถาปัตยกรรมซอฟต์แวร์ ระเบียบวิธีปฏิบัติที่ใช้ในการกำหนดสถาปัตยกรรมโดยใช้แนวคิดการวิเคราะห์ทางเค้าโครงเรื่อง แนวคิดแบบการศึกษา สำนึกและแนวคิดแบบรูปนัย รูปแบบสถาปัตยกรรม ภาษาอธิบายสถาปัตยกรรม การวิเคราะห์และออกแบบสถาปัตยกรรมซอฟต์แวร์ เครื่องมือการกำหนดสถาปัตยกรรมซอฟต์แวร์ การทดสอบเชิงสถาปัตยกรรมซอฟต์แวร์ การนำสถาปัตยกรรมซอฟต์แวร์ไปใช้ในกระบวนการพัฒนาซอฟต์แวร์

Principles of software architectures; practical methods in software architectures using scenario-based analysis, heuristic, and formal approaches; architectural styles; architectural description language; software architectural analysis and design; software architectures specification tools; software architecture-based testing; use of software architectures in the software development process.

## ข้อ 17 — รายละเอียด Term Project

**Minimum requirements for term project**

- There are at lease 3 business use cases (+ authentication) with front-end UI (for demonstration).
- Consist of at least following back-end microservice components:
  - one service (or more) with REST
  - one service (or more) with gRPC
  - one service (or more) with message broker
  - API gateway service
- Describes how to manage Service Discovery.
- Conduct at least 2 types of databases (both RDBMS and No-SQL).
- Conduct a load test (at least 2 types) and explain the results.
- Conduct and explain Risk Matrix.
- Demonstrate at lease 1 issue in SW Quality and measurement. (ex. Scalability, Reusability, Maintainability, Security)

## Term Project Presentation & Submission Guidelines

### 1. Presentation Format & Procedure

- Each group will have 20 minutes total, consisting of:
  - 15 minutes for presentation and live demonstration
  - 5 minutes for Q&A
- Presentations will be recorded via Zoom (link available on MCV) for instructors to review later.
- All groups must arrive at least 15–20 minutes early and be prepared to present ahead of schedule if the previous group finishes early.

### 2. Report Format

- No separate written report is required. Use the provided presentation template (available on MCV).
- Slides should contain all required content and serve as the final deliverable.
- Diagrams must be clearly explained during the presentation. Explanatory text in slides is optional unless necessary.

### 3. Content Requirements

**Part 1: System Architecture Overview**

Use the C4 Model to describe your system's architecture through four levels and supplement with sequence diagram.

**Part 2: Implementation & Demonstration**

Demonstrate your working system and explain key architectural and quality-related aspects. Include the following:

- At least 3 business use cases and authentication
- Live demo of the front-end UI (no recorded videos)
- Back-end architecture must include:
  - At least one REST API
  - At least one gRPC service
  - At least one Message Broker-based service
  - An API Gateway
- Describe the Service Discovery mechanism
- Use at least two types of databases: one relational (RDBMS) and one NoSQL
- Conduct a Load Test and interpret the results
- Conduct and Explain Risk Matrix (at least 3 issues)
- Present and explain 1 measurable Quality Attribute, such as:
  - Scalability
  - Resilience
  - Performance
  - Observability
